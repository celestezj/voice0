# AI 项目全流程方法论（voice0 实战沉淀）

> 本文从 **voice0**（离线实时中文 TTS 系统）从立案到交付的**真实过程**提炼，不是理论清单，
> 而是"踩过坑之后被证明有效"的做法。每一节都给出：**原则**（为什么）+ **怎么做**（如何落地）+
> **voice0 案例**（本项目里对应的具体事件）。
>
> 适用对象：任何"要落地的 AI 工程"，尤其带硬指标（延迟/显存/离线）、需要多方案选型、且有
> 复现/协作需求的端到端项目。可直接作为新项目的检查清单。

---

## 0. 怎么用这份文档

- **立项时**：读「阶段 0-1」，把需求变成可量化指标，建立决策记录。
- **实施时**：读「阶段 2-3」，守住验收纪律。
- **上线/交付时**：读「阶段 4-6」，做对优化与文档。
- **任何阶段卡壳**：读「横切原则」与「反模式」，大概率是踩了已知的坑。
- 它是**清单 + 案例库**，不是教条——每个项目裁剪使用。

---

## 1. 全景：七个阶段 + 五条横切原则

```
立项 → 探索 → 实施 → 测试 → 迭代优化 → 文档沉淀 → 指导复现
  │      │       │      │       │          │          │
  └──────┴───────┴──────┴───────┴──────────┴──────────┴── 横切：见 §9
```

五个阶段之间不是线性走完——voice0 的真实顺序是 `立项 → 探索 → 实施 → 测试 → 迭代 → 文档 → 复现`，
但**文档和决策记录是从第一天就开始写的**，不是最后补的。

## 2. 阶段 0：立项 —— 把需求变成可量化的硬指标

**原则**：模糊需求（"做一个好用的 TTS"）无法验收，也无法选型。第一步是把需求压缩成
**3-5 个可测量的硬指标**，其余是软目标。

**怎么做**：
- 硬指标必须**可测、有阈值、可判定**：如"单句 TTFA <1s""离线（权重缓存后零网络）""RTF 与音质"。
- 硬指标决定架构方向：voice0 的"TTFA<1s"直接推导出"必须流式播放 + 按句分块"。
- 区分硬指标与软目标，软目标排序但不设及格线。
- **指标口径写死**（定义、测量方法、在哪测）：TTFA 是"首包耗时"，RTF 是"合成/播放时长"，
  interval 是"句间空隙"——口径不清，两个人会测出两个数，回归也没意义。

**voice0 案例**：核心指标三句话——TTFA<1s、离线（缓存后零网络）、声音自然（非 SAPI 机器音）。
后两者是软目标，第一个是硬指标，所有架构决策都围绕它。TTFA/RTF 的口径写死在 README 与 bench 代码里。

---

## 3. 阶段 1：探索 —— 选型对比 + 排除项也是资产

**原则**：选型不靠宣传，靠**需求约束剪枝 + 动手验证**。被排除的选项要记录，避免未来重复调研。

**怎么做**：
- **横向对比矩阵**：列维度（音质/延迟/离线/许可/依赖/生态/社区维护），不只看"哪个强"。
- **用硬指标剪枝**：需求"离线"→ 直接排除所有云端方案；"需实时"→ 排除纯自回归端到端。
- **关键假设必须动手验证**：权重能不能下到、实测延迟是多少、显存够不够——宣传数据不算数。
- **主路线 + 可选项双轨**：voice0 把"实时主力"和"音质/克隆可选项"分开，两个后端独立安装互不影响。
  避免"一个方案要满足所有诉求"的死局。
- **排除项写进文档**：为什么排除（fp16 实测更慢 / vLLM 吃吞吐不吃延迟 / 双实例太贵），
  每项是未来省一次调研的钱。

**voice0 案例**：候选清单 MeloTTS / CosyVoice2 / MOSS-TTS-Nano / edge-tts/Azure/火山；
"离线"剪掉所有云端；"<1s 实时"淘汰端到端。MeloTTS 定为实时主力，CosyVoice2 作为可选项接第二后端。
排除的 vLLM/fp16/双实例全部记录在案（含实测数字）。

---

## 4. 阶段 2：实施 —— 抽象边界 + 重构纪律

**原则**：动"正在工作的代码"前先保历史、后保回归；用接口隔离变化，让新功能插拔式加入。

**怎么做**：
- **先重构、后加功能**：纯搬移（`git mv` 保 git 历史）→ 跑通旧用例 → 再动逻辑。
  绝不在"边重构边加新后端"里一步到位。
- **接口抽象**：定义后端协议（`TTSBackend`），引擎只消费统一接口（`synth_stream`），
  新后端实现协议即可接入，差异全隔离在后端内。
- **惰性加载 + 选择性依赖**：核心模块零后端 import；缺依赖时报**清晰错误**（提示装什么）而非崩溃。
  这使"melo-only / cosy-only / both"都能跑。
- **每阶段先回归再前进**：同用例同指标区间对照，过了才动下一步。
- **工程约束显式化**：模型非线程安全 → 统一锁；常驻单例 → 显式生命周期（`close()`）。
  这些是 AI 项目最容易忽略的"进程级"坑。

**voice0 案例**：阶段 A 纯搬移（平铺 → `tts/core` + 后端子目录）先跑通 melo 回归；
阶段 B 引入 `TTSBackend` 抽象；阶段 C 才接 CosyVoice2。backend 参数/voice/stream 变更走"销毁重建"，
mode/normalize 原地切换——生命周期规则写进 README 让后人遵守。

## 5. 阶段 3：测试 —— 验收纪律（本项目最重要的一课）

**原则**：**指标达标 ≠ 输出正确。** 数字漂亮但内容全错，是 AI 项目最贵的失败模式。

**怎么做**：
- **内容级验收**：新后端或改动后必须**转写/试听/人工复核**，不能只看 TTFA/RTF/显存。
  voice0 用 Whisper 转写当"客观裁判"。
- **自动化回归**：bench 脚本自动产出报告并**回写 README 验收区间**——每次改动后对比区间就知道有没有回归。
- **双环境双测**：CPU/GPU 各跑一轮（不同硬件可能暴露不同瓶颈）。
- **探针文化**：一次性诊断脚本（隔离阶段/验证假设/对比 token），用后即弃但**留存输出**。
- **区分"正常波动"与"bug"**：生成式模型有采样随机性（cosy ±1.5× 时长）——判断 bug 前先排除随机。

**voice0 血泪案例（坏 transformers）**：cosy 接入初期 main env 的 transformers 4.57.6 与模型不兼容，
LLM 产出**全错 speech token**，表现为"一句输入 → 多次输出、全是杂音、没完没了"。若只看 TTFA/显存
数字（都"正常"甚至更"好"），就会当成成功发布。**诊断链路**：频谱/基频证明是"人声性噪声"而非白噪
→ 逐模块隔离（flow/hifigan 在参考音频上能还原 ✓）→ 定位到 LLM 生成 token → 版本对比锁定 transformers。
这条链（由现象 → 逐模块排除 → 版本归因）是可复用的排障模板。

## 6. 阶段 4：迭代优化 —— 量化瓶颈先于优化

**原则**：不猜瓶颈，先量化。用数据否定直觉，用收益排序决定投入。

**怎么做**：
- **量化瓶颈**：把耗时拆成 `固定开销 + 边际×量`（voice0 拟合出 `合成≈0.86s+0.82×音频时长`），
  才知道该优化"固定"还是"边际"。
- **用数据否定直觉**：fp16"看似应该快"，实测 RTF 1.215 反而慢 → 排除。记录否定结论和原因。
- **收益排序**：低垂果实（clone 每句省 ~0.4s，纯缓存）优先于高成本改造（双实例流水线，贵且收益小）。
- **优化后内容级验证**：每个优化都跑 Whisper 转写，防止"提速但变错"。

**voice0 案例**：fp16 探针（RTF 1.215 排除）、clone 参考音频缓存（每句 6244→5870ms）、
RTF 瓶颈分解（不是显存，是 LLM 串行解码 + 固定开销）——每次都是先量化再动手。

## 7. 阶段 5：文档沉淀 —— 分层 + 去绝对路径 + 记录坑

**原则**：文档是"别人（含未来的 AI）能接手"的载体。权威设计文档先于代码改动，坑清单按"非显而易见"记。

**怎么做**：
- **分层文档体系**：
  - `README`：快速上手 + 权威设计（引擎怎么工作）。
  - `docs/`：专题文档（某个子系统的完整手册）。
  - **ADR**（架构决策记录）：为什么这么选，含来源与排除项。
  - **CLAUDE.md**（AI 协作地图）：新 AI 会话"冷启动"就能继承项目知识的入口。
- **复现步骤必须环境无关**：**去掉开发机绝对路径**（`D:/anaconda/...`、`E:\temp\...`），
  用"激活环境后 `python`"或占位符（`<参考wav路径>`）。别人没有你的目录。
- **记录"坑"**：非显而易见的、别人会踩的（Python 编码 GBK、依赖版本冲突、模型互斥）。
- **如实记录限制**：cosy 句间停顿、RTF>1、需更强显卡——不粉饰，限制本身就是文档价值。
- **区分"固有代价"与"可优化点"**：明确哪些是**接受的事实**（cosy 句间停顿 = RTF≈1 串行合成固有代价，
  接受）、哪些是**待办优化**（clone 每句重编码参考音频 = 可去掉的浪费，做掉）、哪些是**排除项**
  （fp16 = 实测更慢，否定）。分不清这三类，就会把可优化点当固有代价放弃，或把固有代价当 bug 反复修。

**voice0 案例**：README（引擎 v2 设计权威）、`docs/README-cosyvoice2.md`（cosy 完整手册）、
`docs/tts-architecture-decision.md`（ADR）、`CLAUDE.md`（AI 接手地图）。曾因文档含开发机绝对路径
被用户指出"其他用户哪来这个目录"，全部改为环境无关写法——这条教训值得每个项目都记。

## 8. 阶段 6：指导他人复现 —— 可整段复制 + 版本锁定

**原则**：复现文档的目标是"另一台机器、另一个人，照着做一次跑通"，不是"描述这台机器怎么跑通的"。

**怎么做**：
- **从零复现步骤可整段复制**，顺序执行即成功；依赖版本锁定成表（含已知的坑及规避）。
- **权重/缓存与代码解耦**：预下载脚本 + 缓存重定向到项目内目录，换设备自动重建。
- **选择性安装**：主功能不依赖可选组件；装不了的部件不影响核心。
- **随文档给验收方法**：怎么确认"我复现对了"（跑哪个命令、对哪个区间、看哪份输出）。

**voice0 案例**：README「从零复现步骤」整段可复制（含 conda 建环境、torch CUDA 版、版本锁定表、
常见坑）；权重经 `preload_weights.py` / `preload_cosy.py` 预下载到 `.cache/`（gitignore 不入库）；
melo/cosy 选择性安装互不影响；验收有 bench 自动回写区间 + Whisper 转写脚本。

## 9. 横切原则（贯穿全流程，最容易被新项目漏掉）

1. **小步里程碑式提交**：改动按"可回滚的里程碑"提交，节奏由人类掌控；提交信息中文、描述清楚。
   AI 协作场景下，人类说"提交吧"再提交，不擅自提交、不攒一堆一次性提交。
2. **AI 协作适配**：把项目知识写进 `CLAUDE.md` + 开发者 memory，让后续 AI 会话冷启动就能继承
   （"改引擎前必读 README 常驻引擎 v2""验收必须转写"）。**验收纪律要写进给 AI 的指令**，否则 AI 会只看数字。
3. **决策记录从第一天写**：ADR 不是事后的补丁，是"当时的思考"。排除项、来源、硬件环境都要有。
4. **指标口径与测量方法写死**：定义、工具、位置、对照基线——否则回归无法判定。
5. **失败经验是资产**：坏管线、数字陷阱、绝对路径坑——每一条都写下来，这是别人/未来的你最需要的部分。
6. **"测量先于优化"与"收益排序"**：一切优化决策先有数据，一切投入按收益排序，避免炫技式优化。

## 10. 反模式清单（别这么做）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 指标漂亮就交付，不验证内容 | "数字达标但输出全错" | 内容级验收（转写/试听） |
| 重构和加新功能一步到位 | 回归难定位 | 先纯搬移回归，再动逻辑 |
| 文档写开发机绝对路径 | 别人无法复现 | 环境无关写法 + 占位符 |
| 选型只看宣传不实测 | 接完发现延迟/显存不达标 | 关键假设动手验证 |
| 不记录排除项 | 未来重复调研踩坑 | 排除项 + 实测数字入文档 |
| 优化前不量化瓶颈 | 优化到不痛的地方 | 先拟合固定/边际，再排序 |
| 复现文档按"我机器怎么跑"写 | 换机即失败 | 从零到跑通的整段复制步骤 |
| 生成模型随机波动当 bug 修 | 白费力气 | 先排除采样随机性 |
| 模型非线程安全却并发调用 | 偶发崩溃/错乱 | 统一锁 + 生命周期显式化 |
| 缺依赖报裸 ImportError | 使用者不知装什么 | 清晰错误提示安装步骤 |

## 11. voice0 案例时间线（方法论 ↔ 事实对照）

| 阶段 | 方法论条目 | voice0 实际事件 |
|---|---|---|
| 立项 | 量化硬指标 | TTFA<1s / 离线 / 自然 → 决定流式架构 |
| 探索 | 对比矩阵 + 剪枝 + 双轨 | MeloTTS 实时主力 + CosyVoice2 可选项，云端排除 |
| 实施 | 先重构后加功能 | 阶段 A 纯搬移回归 → 阶段 B 抽象 → 阶段 C 接 cosy |
| 测试 | 内容级验收 | 坏 transformers 杂音被 Whisper 揭穿 → 版本锁定 4.51.3 |
| 迭代 | 量化 + 探针 + 收益排序 | fp16 排除、clone 缓存每句省 0.4s、RTF 瓶颈分解 |
| 文档 | 分层 + 去绝对路径 + 记坑 | README/docs/ADR/CLAUDE.md 四层，绝对路径全部清除 |
| 复现 | 整段复制 + 版本锁定 | 从零复现可整段复制、权重预下载、选择性安装 |
